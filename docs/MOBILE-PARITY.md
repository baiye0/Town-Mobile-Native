## 队列状态与持久化

- `queued` → `preparing` → `sending` → 完成后移除；202 改为 `waiting`。
- 在发送前获取历史 seq 基线，避免把旧的同文消息误当作本次成功。
- 已开始发送的记录重启后只能读取回放/历史。只有明确拒绝或发送前的失败进入可重试状态。
- 游标和正文在同一个队列快照中保存；流式过程中最多约每 0.5 秒落盘一次，恢复时从同一快照续接。
- 保留未确认消息、失败队列和原文件；损坏的队列文件不会被新发送覆盖。
- 附件草稿按连接和场景隔离。含待处理队列的场景不能删除。

## 明确未达到桌面完整对等的部分

1. **后台推送**：这是客户端本地完成通知，不是 APNs/FCM。系统挂起、杀掉进程或设备离线时，不能承诺即时通知；回到应用后恢复查询。当前仓库没有对应推送服务端注册/投递链路。
2. **交互界面高级协议**：不执行 `app` JavaScript，不支持 diagram、tabs、图片组件、跨轮 surface patch/baseRevision 与旧版界面回看。遇到这些内容保留源码并说明不支持；向模型声明的能力仅包含本地已实现的组件。尚未宣称完整 Intelligent UI Beta 对等。
3. **Office 文件预览**：iOS 和 Android 使用平台查看能力；Android 是否能显示某种格式取决于已安装的查看器，解析文字可作为阅读入口。没有把桌面 PPTX/XLSX 渲染器移植到原生端。
4. **队列调度**：可在生成中创建/切换场景；“停止当前回复并优先发送”采用明确 stop 确认后再发送的方式，不模拟服务端的任意 splice 调度。
5. **SBS**：对话顶部提供绿色状态点与设置面板：开启时绿色、关闭或未知时空心，活动期间呼吸动画；正文显示按场景保存；全部场景强制包含正文。自主醒来通过 `/api/llm/config` PATCH 并以服务端回执更新开关。对话页前台每 10 秒读取活动快照和配置，区分思考、工具、回复与回调；开启正文时同步历史。没有独立后台常驻订阅，短暂活动可能在轮询间隔内结束。
6. **真实写入验收**：没有使用真实凭据替用户发送对话、私信、上传文件、修改模型或登记通讯录。编译和核心规则测试不能代替这些完整链路验收。
